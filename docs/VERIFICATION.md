# v0.1.1 验证记录

验证日期：2026-09-12。Windows x64，.NET SDK 10.0.401，随包 7-Zip 26.03。

## 本次修复验证

- 导入共同父目录、多个子目录或多个文件时，跨目录关联互补分卷；`.part1.exe` 与 `.part2.rar` 使用一致的名称族。
- 桌面流程验证先添加文件夹 1、后添加文件夹 2：自动合并成单任务、保留取消勾选状态，验证后集中解压，恢复后返回原位置且内容一致。
- 重新导入保留完成任务身份；新增重复序号使原自动分组转为待确认；旧任务成员丢失时，新增成员仍可手动确认，不替换原任务身份。
- 跨目录整理的名称冲突、哈希变化、中断恢复、重试身份、跨盘拒绝和日志范围校验；旧版同目录日志仍可恢复。
- 基于允许再分发的 RAR 测试夹具构造自解压首卷，验证程序头偏移计入分卷总大小；跨目录智能停止检查全部成员。
- 用户实际双分卷文件通过只读扫描与隔离副本的引擎列表／卷数／大小校验；原文件名和内容哈希保持一致。该包加密，未输入其密码，未执行实际内容解压或移动原件。用户样本不进入仓库和发布包。

## 已验证

- 解决方案 Release 构建：0 个警告、0 个错误。
- 核心、引擎及兼容性自动测试：96/96 通过。
- WPF 窗口流程：添加与选择任务、跳过任务、解压、错误密码后重试、智能停止与继续内层、手动分组、改名后取消并首次重试、拒绝替换成无关同名文件、拒绝修改后的目标文件、失败状态颜色。
- 三层实际链路：SFX EXE → 伪装编号分卷 → TMP 7z → 正文文件，两层使用不同密码。
- ZIP 普通、字节切分及原生 z01 分卷；ZIP64 仅偏移字段使用扩展记录的小型结构夹具。
- 有固定来源、许可和 SHA-256 的真实 RAR5 八分卷；真实 RAR4/RAR5 单包的数据加密及文件名加密，错误密码后重试、解压内容和恢复哈希均验证。
- 改名前核验全部分卷确实被引擎使用；缺卷、额外无关卷、错误格式及未使用尾部数据不执行改名。
- 改名恢复、冲突、内容修改、模拟中断、损坏日志路径交叉、路径越界、链接元数据、大小写冲突、取消运行中的子进程。
- 便携程序在禁用系统运行时查找并将运行时目录指向不存在路径时正常启动；宿主跟踪确认从便携目录加载 CoreCLR，包内解压引擎哈希匹配固定清单。

## 验证边界

- 运行时隔离启动测试不等同于在全新 Windows 虚拟机执行所有流程；未卸载本机已有运行环境。
- 用户实际加密分卷仅验证识别与结构；真实加密 RAR 分卷的完整内容解压、超过 4 GiB 的完整 ZIP64 归档仍未完成端到端样本验证。
- ZIP 原始文件名额外检查；7z/RAR 的控制字符可能被引擎规范化。超大 SFX 外壳与特殊格式见 README 限制。
- 未对本机恶意并发进程执行文件替换竞态攻防测试。处理期间不要外部移动、修改输入文件。

## 复现

```powershell
dotnet build AutoExtractor.sln -c Release
dotnet run --project tests/AutoExtractor.Tests -c Release
dotnet run --project tests/AutoExtractor.App.SmokeTests -c Release
./scripts/build.ps1
./scripts/verify-portable.ps1
```

`scripts/build.ps1` 默认执行全部测试、打包和便携启动验证；GitHub Actions 使用同一脚本。夹具内容只用于解压测试，从不运行其中程序。测试、构建中间文件和本地宿主跟踪不进入源码仓库或发布包。
